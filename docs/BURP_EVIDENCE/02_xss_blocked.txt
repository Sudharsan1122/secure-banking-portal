BROWSER EXECUTION DEFENSE ANALYSIS:
--------------------------------------------------------------------------------
1. Storage Stage: The backend accepts raw strings in the database to prevent double-encoding bugs,
   while detecting `<script` signatures to log `XSS_BLOCKED` telemetry into SIEM.
2. Display Stage (Dashboard / Ledger): In `js/dashboard.js`, DOM elements are populated exclusively
   using:
     `tdRemark.textContent = tx.remark;`
   The browser converts the `<script>` tags into literal display text. The HTML parser is never invoked.
3. Defense-in-Depth (CSP Nonce): Even if a developer erroneously used `innerHTML = tx.remark`,
   the browser immediately blocks execution with the following console security violation:
   "Refused to execute inline script because it violates the following Content Security Policy
    directive: script-src 'self' 'nonce-9c3f2e1a8b7d6c5e4f3a2b1c'. Either the 'unsafe-inline'
    keyword, a hash, or a nonce is required to enable inline execution."
