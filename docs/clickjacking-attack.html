⚠️ Adversary PoC: Clickjacking / UI Redressing ATTACK SIMULATION

Attack Vector Scenario:
An attacker embeds http://127.0.0.1:8080/frontend/transfer.html inside a transparent or deceptive iframe layer.
The attacker lures the victim into clicking a decoy button ("Claim Free Gift!"), which is visually aligned directly over the banking portal's "Confirm Transfer" CTA.

Attempted Iframe Embedding Sandbox:

The red dashed box below attempts to frame the SecureBank transfer page:

🎁 Click here to claim your $1,000 reward! (Decoy Button)

🛡️ Why This Attack Fails (SecureBank Mitigation):

  1. X-Frame-Options: DENY: Server sends X-Frame-Options: DENY on all responses. The browser strictly refuses to render the page inside any frame, iframe, or object tag regardless of origin.
  2. CSP frame-ancestors 'none': Content-Security-Policy 2.0 directive reinforces frame protection at the W3C standard level, overriding legacy browser behaviors.
  3. Browser Enforcement: If you open DevTools Console (`F12`), you will see the browser security log:
    Refused to display 'http://127.0.0.1:8080/frontend/transfer.html' in a frame because it set 'X-Frame-Options' to 'DENY'.
